Three rules

Accepted means stored: the API answers 202 only after the record is written. One owner: only the Wire II API writes a wire's request and outcome; the Sweeper only decides who sends it next. Safe to repeat: the same stored request and the same key go out every time.

How Wire II moves one wire

Two services, one small Lambda and one record. The Wire II API owns the content of the record. The Submitter does the work that depends on third parties and reaches the record only through the API. The Sweeper is the safety net and writes only who sends a wire next.

The Sweeper calls none of these. It writes the table directly: request dispatch, name the probe, adopt, park.

Retries: two nets that do not overlap

  1. SQS redelivery handles normal retries. After a failed attempt the same message comes back after 30 seconds, then 1, 2, 5, 10 and 15 minutes.
  2. The sweeper acts only when a record has had no progress for about 20 minutes, which is longer than any of those waits. It covers a lost message, a dropped pipe event and a status PayX was never told.
  3. A timeout or a 5xx is never retried at once inside an attempt, because OPF may still be working on the first request.

One table, two kinds of rows

DynamoDB fixes only the key of a table. Every other field belongs to the individual row, so rows of different kinds can share one table. The Transactions table holds two kinds, told apart by recordType.

recordTypeKeyHow manyFields
WIREThe UETROne per wireStored request and hash, status, ownerRegion, dispatchRequested, attempts, unansweredAttempts, leaseUntil, checkAt, opfResponse, statusReported, parkedReason.
BREAKERus-east-1#breaker#OPFFour: OPF and Turing in each regionstate, failedUetrs, openedAt, nextProbeAt, probeUetr, lastProvenAt, checkFailures.
  1. A wire row carries no breaker field. "The breaker opens" is one write to one breaker row, and it affects every wire because the API reads that row on each lease request.
  2. The pipe never queues a breaker row: it has no ownerRegion and no dispatchRequested, so the filter does not match.
  3. The sparse index never lists one: it has no checkAt.
  4. The global table copies breaker rows like any other row. That is how us-west-2 reads the breaker of us-east-1.
  5. Anything that reads the table or its stream in bulk, such as a report or an export, filters on recordType.
  6. A separate small global table for the breaker rows would work equally well and change nothing else. It would cost one more table to provision, encrypt and replicate.

The breaker

One small record per dependency and region, kept by the API. It is a row of its own in the transaction table under a reserved key such as us-east-1#breaker#OPF: not a field on each wire and not a separate table. The global table copies it, so the other region can read it. The scenarios show this row beside the diagram whenever a step reads or changes it. The gate is the lease: a Submitter cannot call OPF without one.

FieldMeaning
stateCLOSED, OPEN or PROBING.
failed UETRsThe different wires that failed in a row. A clear answer from OPF empties it.
nextProbeAt, probeIntervalWhen the next test wire may go out. The interval doubles after a failed probe: 1, 2, 4, 8, then 15 minutes.
probeUetrThe one wire that may have a lease while probing.
openedAtWhen it opened. The other region takes over the sending five minutes later, if it is able.
lastProvenAtThe last clear answer from OPF, or the last path check that got through. A closed breaker with an old value proves nothing.
checkFailuresPath checks that failed in a row. Three open the breaker, so a quiet region notices a broken route before the first wire is hurt.
  1. It opens when five different wires in a row have failed. One wire that keeps failing cannot open it.
  2. While it is open, leases are refused and the Submitter deletes the message. Wires wait in the table. No retries are used up and the API keeps accepting.
  3. FIS has no health endpoint, so the test that closes the breaker is one real wire. A clear answer from OPF, accepted or rejected, closes it.
  4. The path check is one authenticated call to FIS that creates no payment. It runs when a region has proven nothing for a minute. A wire is spent as a probe only after a path check got through, and a region with no wire waiting closes its breaker on the path check alone.
  5. After it closes, the sweeper pushes the waiting wires oldest first, 60 per sweep.

The deadline and a parked wire

Each wire gets a submit deadline when it is accepted: the earliest of how long FIS remembers a key, the cut-off of the wire, and how long product allows it to wait. No lease is granted after it.

ReasonIt meansFor the operator
NOT_SENTThe deadline passed and nothing ever reached OPF.A replay is always safe.
OUTCOME_UNKNOWNAn attempt went out without a clear answer. OPF may hold the wire.Check OPF before anything else.
MAX_RECEIVESThe wire failed for about two hours while others succeeded.Look at the cause, then replay the record.

The dead-letter queue

A queue message is only a pointer to the record. SQS moves a message to the dead-letter queue when it has failed too often. That stops the retries and fires an alarm. The wire is still in the table, and the sweeper keeps it moving. Nobody cleans the dead-letter queue: its messages are deleted by SQS 24 hours after they were created, and the alarm clears when no more arrive. An operator replays a parked record through the API, never the message.

What Payment Exchange is told

OutcomeIt means
AcceptedOPF has the wire. PayX produces WIRECLEARING.
RejectedThe wire was refused. PayX produces WIRECLEARING.STOP.

Nothing is reported while a wire is retrying or parked. If the final status is late, PayX alerts and sends the same request once more. That replay is always safe, and it is the only cover for a wire that was accepted just before a region was lost and never copied.

Two regions

  1. us-east-1 serves the traffic and us-west-2 is a warm standby with its own pipe, queue, Submitter and Sweeper. Routing sends calls to a region whose API is healthy.
  2. Each pipe passes only the records of its own region, so a copied record is never dispatched twice.
  3. Able: a region's breaker is closed and it has proven its path to OPF in the last three minutes. Out: its breaker has been open for five minutes, or it has proven nothing for five minutes.
  4. When one region is out and the other is able, the able region's Sweeper adopts the other's unfinished wires, 60 per sweep, and sends them. This covers a lost region and a region cut from OPF with one rule, and needs no routing switch.
  5. When both breakers are open, OPF itself is down. Nobody adopts. The wires wait where they are.
  6. A lease is not a lock across regions. Protection comes from the rule above, which cannot hold in both regions at once, the region filter on the pipes, and the same key and bytes at OPF.

Before go-live

FIS must confirm in writing how OPF treats a repeat with the same key and body, and it must be tested in the FIS sandbox with two repeats arriving together. FIS must allow the outbound addresses of both regions. A regional failover must be rehearsed in a lower environment.
